# P0-4：有界事实一致性与答案修复

[FRAME | HIGH] 2026-09-06，用户授权继续实现 P0-4；前置 P0-3 已合入 `1bdd92a`。设计版本 v1，准入 `TDD_INPUT_READY`。

## 设计树与接口

```text
P0-2 required-query completion → P0-3 Accepted Evidence + model answer
  P0-4 / FACT_CHECK [已验证：A1/A2]：引用范围、精确数值、单位、显式陈述一致性
    通过 → P0-4 / ADMIT [已验证：A3/A4]：原有全部校验通过才交付
    失败 → P0-4 / REPAIR [已验证：A3]：原始问题 + 同批证据 + 安全错误码
      策略允许 → 最多一次修复 → 全部重验 → 交付或拒绝
      策略/预算拒绝 → POLICY_DENIED
P1-1 long-context task state [待执行]
```

[FRAME | HIGH] 使用现有 FinalAnswerOutput，不要求模型自报分数或支持声明。Control Plane 检查 message 中的数字与显式陈述；只使用实际引用的 Accepted Evidence 正文及经过完整性检查的 typed fields。来源 ID、引用 URI、问题和会话中的数字不能充当支持。候选和拒绝证据不能充当支持。

[FRAME | HIGH] 此阶段采用保守、可解释的确定性校验：数字使用 Decimal 精确归一化，保留单位、主体、字段、极性及条件；数值句须匹配同一事实的来源表述，不做聚合、推算或单位换算。支持短句、字段赋值和英文 is/are、中文是/为的显式陈述。类型字段转换为独立事实，false/null 不视为缺失或零。多 typed record 必须带 record_id 区分。显式陈述无支持或冲突时拒绝；未识别的自然语言明确记录为未覆盖，不能称为通用语义验证。保守匹配可能拒绝正确的自由改写。

[KNOWN | HIGH] 实现仅对显式陈述值中的独立数量 token 归一化；主体、记录 ID 和字段名精确保留。零填充代码、typed string/date/datetime/boolean/null 使用字面值检查；单位大小写及数学、货币符号不删除。已知 typed subject 优先于通用分隔语法，避免字段名中的 `is`、冒号或“是”被误解析。无显式谓语的数字句要求原文匹配。仅 `CNY`、`RMB`、`yuan` 使用同一货币标签；没有汇率或数量级换算。

[KNOWN | HIGH] 单次事实检查上限为答案 16,000 字符、证据 128 条/合计 1,000,000 字符、来源与答案合计 2,048 个语句。超限以 `fact_check_input_limit` 失败。上述限制不替代已有模型上下文策略；一次修复指一次逻辑修复，已有上下文溢出传输重试规则保留。

## 验收

1. **A1 / FACT_CHECK**：固定基线 100 正确通过，500 错误拒绝；精确小数、大整数、单位错配、主体/字段互换、无引用/未引用/未准入来源不能支持数值。
2. **A2 / FACT_CHECK**：肯定/否定、限定条件、枚举、false/null 的显式陈述正反例；同主体冲突拒绝；非识别句有覆盖说明；超出有界输入拒绝，诊断不含正文/金额。
3. **A3 / REPAIR → ADMIT**：同一公开 runner 执行修复成功、仍错误、策略预算拒绝；混合 safety 失败不修复；总修复一次，修复再次通过所有原门控。
4. **A4 / 集成**：原有 required-query、typed evidence、初次与修复答案行为回归；独立基线自然转绿，长对话缺口保留；后端适用检查、领域索引与文档同步。
