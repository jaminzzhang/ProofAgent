## 用户目标与实际覆盖

用户问：“平安御享一生终身寿险保障怎么样？我现在30岁，是否适合买？”
以下是针对该问题的人工审阅，不是产品销售建议，也没有重新核验当前公开条款版本。

| 需要回答的内容 | 既有捕获支持与缺口 | 最终答案表现 |
| --- | --- | --- |
| 具体产品和版本 | 检索命中分红型条款，但用户未指定分红型；版本最新性未验证 | 提及分红型，没有解释采用的版本范围 |
| 主要保障如何计算 | 有身故保险金两项取大的关系、给付比例表与到达年龄定义 | 仅说提供身故保障，未解释主要给付机制 |
| 产品的条件、限制及其含义 | 有终身期间、分红不保证、退保损失等说明；无个人保费/现金价值方案 | 罗列事实，没有组织成帮助用户判断的解释；分红不保证重复出现 |
| 30岁与是否适合的关系 | 年龄是用户已知事实，个人目标、支付安排、已有保障等尚未形成输入 | 没有回答，也没有说明还缺哪些判断条件 |
| 免责条件 | 捕获有免责父句及若干子项，但不能据片段认定覆盖完整免责清单 | 直接列出三个行为片段，丢失“导致身故则不承担给付责任”的父条件 |
| 下一步如何推进 | 可以先交付有依据的产品解释，再聚焦必要个人背景及缺失方案资料 | 没有有效下一步或问询 |

年龄本身不足以产出适配结论，并不意味着可以完全省略这一子问题。合理交付应明确当前判断边界、解释判断需要什么，并继续获取必要信息。

## 根因与实现位置

### 1. 高优先级输出契约主动限制分析

[KNOWN | HIGH] [harness_helpers.py](../../../proof_agent/control/workflow/harness_helpers.py) 的普通回答system要求文本证据逐句原样选取，禁止合并、改写、增加解释性标签，以及将表格转成新文字断言。阶段配置虽然要求回答核心问题、解释条件和给出下一步，但不能覆盖system契约。

因此，这次不能主要归因于Dashboard Prompt没保存或上下文没传到模型。捕获确认Workflow配置和Skill补充已传入；更高优先级契约却限制了它们能产生的回答。

### 2. 事实一致性校验无法区分合理解释与错误推导

[KNOWN | HIGH] [answer_facts.py](../../../proof_agent/control/validators/answer_facts.py) 使用来源近似形式的主语和值匹配；它不是通用语义蕴含判定。首次回答包含改写、表格解释、用户年龄与适配边界说明，这些不能统一按“必须在来源原句中出现”判定。

不过，首次回答也不能直接恢复为最终答案：它在适配段将用户当前30岁直接对应160%档位，未在该处保持“身故当时到达年龄”的条件。捕获条款明确按身故当时年龄计算。该表述会使用户误以为投保年龄锁定将来给付比例，应修正条件绑定。

[INFERRED | HIGH] 当前故障既有合理转述受限，也有模型实际条件推导不严谨。简单关闭事实校验无法解决问题。

### 3. 修复改变了交付能力，并丢失条款结构

[KNOWN | HIGH] [final_answer_attempt.py](../../../proof_agent/control/workflow/controlled_react/final_answer_attempt.py) 在文本事实失败后切换到 `selection_request`；[answer_source_selection.py](../../../proof_agent/control/workflow/controlled_react/answer_source_selection.py) 对普通问题只接收 `statement_ids`，随后排序并以换行拼接。

来源选句还有结构限制：[answer_facts.py](../../../proof_agent/control/validators/answer_facts.py) 会滤去以冒号结束的句子和部分列表/富文本项。本次精确核对确认免责父句存在于证据，却不在候选句及最终答案中，子项仍然可选；逐句真实不保证组合后条件完整。不同句子的原文身份也不能保证没有语义重复。

同样，三档给付比例在已准入证据中各出现一次，但在84个候选句中全部消失。这意味着单靠修复阶段选句，模型已无法交付完整的给付机制解释；它不是单纯选错了几句话。

### 4. 完整性没有成为该任务的交付门槛

[KNOWN | HIGH] [answer_requirements.py](../../../proof_agent/control/knowledge/answer_requirements.py) 当前仅对受支持的业绩分析profile提供确定性完整性状态；本问题所有要求都保留 `unassessed`。普通Run允许输出带引用的部分内容，因此成功终态与用户感知的“完整回答”存在差距。

Intent另外将必要个人背景留空，并把适配查询设为可选。无论后续模型多强，当前必需工作集合都没有要求它覆盖第二个业务诉求。

### 5. 次要上下文问题

[KNOWN | HIGH] 捕获的Agent purpose仍含旧KSS绑定描述；这与当前external Knowledge运行事实不一致，应在后续配置整理中清理。它不是本次条款拼接的主要原因；本次没有改写用户配置。

## 改进方向与验收用例

[INFERRED | HIGH] 优先围绕“事实—条件—推导—用户缺口—结论”建立可验证的回答结构，再调整Prompt，而不是单独增加“深入分析”要求。

1. **任务覆盖**：保障解释和适配判断分别形成必需交付要求；必要个人信息明确标为缺口。能解释的先回答，需要用户的信息再聚焦问询。
2. **事实与推导分层**：产品事实绑定条款锚点；条件推导记录前提和适用范围；用户输入注明来源；问询和无法判断说明不要求伪装成条款原句。验证不依赖展示或保存原始思维链。
3. **保留条款单元**：给付公式、年龄表、定义、免责父句与子项作为关联单元处理。允许通俗解释，但禁止改变事件时间、条件、金额、保证性质及例外。
4. **有针对性的修复**：只修错误事实/条件/引用，保留已支持的解释和未回答要求。确需回退摘录时，用户可见地说明回答范围及未完成项；不能让摘录覆盖掉原问题。
5. **分开评估**：引用可追溯、事实正确、推导有效、问题覆盖、可读性分别验收；不能以“来源ID有效”代表业务通过，也不能凭模型自评授予权限或完成状态。

建议将本Run纳入开发回归，并另设未用于调试的同类任务：

| 验证案例 | 必须通过的判据 |
| --- | --- |
| 原问题：产品解释＋30岁适配 | 两项诉求均有处理；信息不足时给出判断边界与必要问询，不能静默遗漏 |
| 当前30岁、未来不同年龄的事件条件 | 给付档位绑定事件时年龄；拒绝将投保年龄永久固定为给付比例依据 |
| 同义转述与事实篡改对照 | 保持条件/数值的通俗解释可接受；篡改比例、事件时点或保证性质必须拒绝 |
| 免责条款父子结构 | 每个免责说明保留触发条件与免责后果，不输出孤立行为列表 |
| 缺少投保范围/现金价值/个人方案 | 继续定向检索或明确缺口，不从产品类别、集团业绩或用户年龄推断具体方案 |
| 首答局部失败后的修复 | 修正错误后仍覆盖原问题；如只能部分回答，保留未完成项和下一步 |
| 相近名称或分红型版本不明 | 明确当前证据对应版本；不声称已经验证最新版本或自动套用其他版本 |
