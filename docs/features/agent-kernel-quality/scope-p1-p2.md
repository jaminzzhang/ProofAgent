[FRAME | HIGH] 2026-09-06，用户要求「规划并执行 P1、P2」。实施起点为 `main@586a565`，开发分支 `codex/kernel-p1-p2`。沿用原有五个切片 ID，按依赖推进；独立规划与实现专项可以并行，公共契约和整体验收由主 Agent 汇总。本计划不授权真实业务系统的未指定写操作或生产发布。

## 项目主流程与目标树（v3，2026-09-07 本地验收）

```text
Operator request + persisted conversation
  P1-1 / TASK_STATE [有界本地验收通过]
    用户目标/约束 → 有来源的工作状态 → 实际模型上下文
    纠正/撤销 → 更新有效状态；冲突/放不下 → 明确未解决
  已有 Intent + Skill Admission + Required Retrieval
    P1-4 / SKILL_BOUNDARY [有界本地验收通过]：已绑定资源、领域扩展、权限只收窄
  P1-2 / TASK_EXECUTION [有界本地验收通过]
    固定必需工具目标/依赖 → 原 Tool Gateway → 验证结果 → 完成证明
    查询 → 确定性计算 → 可验证报告 → 原 Artifact Finalization
    失败/取消/预算耗尽 → 不宣称完成，不交付未验证产物
  P1-3 / BUSINESS_ACTION [本地模拟验收通过；真实动作待明确]
    精确服务端授权 → 原子执行账本 → 调用 → 结果核验
    重复 → 重放；未知 → 对账；补偿 → 独立授权操作
  已有答案门控/Run 可见性提交
P2 / MEASURE_AND_VERIFY [有界本地验收通过]
  固定场景与源码绑定 → 延迟/模型调用/Token 测量 → 真实依赖与发布证据
  缺失/未运行/不匹配 → 保留失败或未验证，不能生成通过证明
```

## 切片契约与验收

| ID / 节点 | 输入、处理与输出 | 依赖与边界 | 验收 |
|---|---|---|---|
| P1-1 / TASK_STATE | 有序用户问题及同会话已持久化状态；目标、约束、明确纠正/撤销经 Control Plane 归约；输出有内容且有界的模型工作上下文，随 turn 原子持久化 | 复用 ConversationTurn、现有 local/Postgres JSON 与并发控制；assistant/知识内容不能改目标或赋权 | 30/100 轮实际 ModelRequest；纠正、撤销、冲突、预算不足；关闭重建存储；当前请求立即生效；无证据时仍不能满足检索门 |
| P1-2 / TASK_EXECUTION | 固定工具需求与无环依赖，模型提议经名称/参数/预算/前置验证；结果与同 Run 真值绑定；仅已验证结果生成受控报告 | 使用原 V3、Tool Gateway、Truth 与产物提交，不建第二执行器；计算首版只支持明确的精确十进制运算，未知运算/单位不推断 | 多工具顺序、跳步/伪完成拒绝、失败传播、结果篡改、预算、取消；报告内容与 digest；恢复不重复已证明的步骤 |
| P1-3 / BUSINESS_ACTION | 可信主体、精确操作/资源/参数摘要、版本和期限；原子预留、幂等冲突、执行 fencing、独立结果核验及 unknown 对账 | 先完成本地契约和模拟端口；生产工具仍只读。真实业务对象、动作、远端幂等及补偿规则待明确 | 缺授权/过期/撤销/错主体/参数漂移；并发与重复；提交前中断、未知结果、旧执行者；补偿不等于通用回滚 |
| P1-4 / SKILL_BOUNDARY | Package 内已绑定 Skill 定义和资源；有界加载、冻结及路由准入；第二领域参考使用同一内核 | 复用 BusinessFlowSkillPack，不能安装工具、扩大参数、跳过策略或成为证据；第二领域放内部验收 fixture | 越界路径/符号链接/过大/重复/未知引用拒绝；两个领域通过同一入口；恶意 addenda 不能扩大权限 |
| P2 / MEASURE_AND_VERIFY | 固定版本、固定样本和实际运行观测；输出可重复性能/用量报告和验证状态 | 与质量率、生产 Gate 权威分开；真实依赖需要已明确的非生产环境；沿用五个顶层 Release Gates | 样本缺失/变化、失败、未评估不能改善结果；运行时测量；现有真实依赖测试和完整 Gates 的实际执行/缺口逐项记录 |

## 实施依据与未决项

[KNOWN | HIGH] P1-1 当前只取最近 3 轮，压缩摘要仍为轮数占位；统一入口是 `control/conversation.py`，模型内容由 `context_assembler.py` 与 `harness_helpers.py` 消费。P1-2 的 `composition.py` 在任一工具结果后直接回答，`bootstrap/validation.py` 将工具预算限制为 0/1；仅改配置上限不能证明完成闭环。

[KNOWN | HIGH] Skill 的路由、准入和工具范围解析已存在，但执行中发现 Skill 引用未落实到运行时工具范围；P1-4 已补上该限制。业务写入在 Gateway 和生产准入中均关闭，旧 `approved=True` 不是精确业务授权。P2 正式外部知识库发布 profile 和真实 Dify 验收尚未完成，旧 KSS 证据不能替代它们。

[FRAME | HIGH] P1-1 首版支持显式目标/约束标记及可确定的中英文预算、禁止动作和按 key 的修订；未知自然语言不伪称理解。状态只用于任务连续性，不提升记忆为证据或权限。P1-3 真实动作和 P2 联调环境已向用户询问；未收到明确输入前，只完成不依赖它们的工作，不把等待时间当授权。

[FRAME | HIGH] 预计涉及会话、工具控制、产物、Skill 加载和测量五个独立验收边界；无法仅凭现有信息可靠承诺总工时。每个切片保留原 ID、开始/收口状态和实际测试证据。整个 P1/P2 只有必需节点和跨节点验收完成才可宣称完成；部分本地通过保持部分覆盖。
