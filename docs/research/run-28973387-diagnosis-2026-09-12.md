## 优化方案（建议，未实施）

### P0：从事实列表升级为受证据约束的业务分析

保留当前 source selection 的安全性，将平铺 IDs 扩展为受控分组：

- reporting_period 和 comparison_basis：由证据绑定；默认明确采用同板块同比，并单独标出较年初指标，不能混为一谈。
- business assessments：business_id、dimension、assessment（改善/承压/有增有压/证据不足）、supporting_statement_ids、counter_statement_ids。
- answer requirements：亮点概括、哪些业务表现较好、哪些业务存在压力、哪些范围无法判断。
- 每条候选事实应携带来源绑定的业务、期间、指标、单位与比较基准。原文中省略主语的“实现净利润…”不能任意归到另一板块。

业务和指标绑定来自已准入材料/明确源上下文；模型仅提议分组，不自授评判权限。控制层校验实体、期间、方向、反证及引用，再模板渲染“业务—表现—依据—限制”。有限规则不认识的指标只能给原文或证据不足。未知实体、错板块、错比较期间和无依据结论必须拒绝。保持现有预算与有限修复，不退回无约束自由写作，也不机械调高 16 条上限。

“没有负面证据”不能推出“表现好”；“某指标下降”不能推出“整个业务差”。允许同一业务同时出现增长亮点与经营压力。跨业务不同指标（NBV、利润、成本率）不能按增长百分比直接排序。“承压”的领域规则也应版本化；例如拨备覆盖率下降单独不足以推出资产质量恶化。

### P0：将问题覆盖与事实正确性分别校验

最终检查必须同时满足：问题分项有直接回答；每项明确业务和比较口径；判断有支持、相关反证未丢；缺口具体披露。总体 scope 免责声明不能替代逐项回答。检索覆盖和最终回答覆盖分别计算，候选里有负面事实不等于最终回答用了它。

新增回归：本 run 指标列表应失败；只加标题仍失败；同一业务正负混合不得二元强分；错配业务/期间失败；丢弃已知相关负面事实失败；全部缺少负面材料时允许明确无法判断且不能捏造“较差”；有证据支持的分组回答通过。离线真实输入加对抗样例先验证，再经授权做真实模型验收，分别记录事实正确性、问题覆盖、引用、修复次数和成本。

### P1：按业务缺口检索

用“业务×指标维度×期间×支持/反证”覆盖矩阵代替三个全局关键词。初查定位报告期及板块清单；对缺口定向查询，例如寿险价值增长与价值率、产险成本率与承保利润、银行利润与净息差/资产质量。只有用户范围或报告板块清单确认的板块才加入要求，避免硬编码某公司清单或无限搜索。单业务变化不足以代表集团全面覆盖，预算耗尽时输出已有结论及明确缺口。

### P2：改写及可观测性

改写应替换完整时间限定短语并保留报告类型，不能留下“报”残片。可观测性分别报告检索成功、证据准入、事实一致性和问题完成度；新增 Trace 只保留稳定类别/计数/受控缺口码，敏感证据留在既有受控 capture。
