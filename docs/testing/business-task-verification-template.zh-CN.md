# 业务任务验证用例模板

适用于 ProofAgent 的问答、资料分析、受控只读工具和交付物任务。核心目标以
[共享规则](../../AGENTS-COMMON.md#product-goals-and-design-acceptance) 为准；
产品范围以 [PRD](../prd.md) 和 [技术设计](../technical-design.md) 为准。

这是可复制的案例设计文档，不是可直接加载的 Evaluation Suite、运行时契约或新发布 Gate。
将完成的案例放入 `docs/features/<feature-id>/`，关联相应测试与执行证据。
仅选择该任务涉及的验证维度；不适用项写明理由。

## 1. 设计方法与判定边界

1. 从真实业务目标和用户原话出发，先写成功与不可接受结果，再选择实现和测试入口。
2. 为每个必需子问题建立稳定 ID，分别定义证据、输出、判断方法；隐含意图或无法自动验证的要求单列。
3. 定义来源、期间、适用性、条件、权限与预算；不要从模型答案倒推出标准答案。
4. 给关键行为配成功、错误、缺失和边界对照。改变数字、期间、条件或遗漏子问题后，判定应相应改变。
5. 通过项目现有执行入口生成运行证据；评估读取明确绑定的运行制品，不另建绕过 Control Plane 的执行链路。
6. 分开记录运行终态、治理检查、事实正确、任务完整和案例预期是否匹配。
   `ANSWERED_WITH_CITATIONS`、来源支持或模型自报完成，都不能单独证明业务完成。

本模板中的人工业务判定用于独立质量记录，不自动变成现有 Analyzer 的语义 Gate。
人工或模型评审不能覆盖失败的确定性门禁；未实现的自动判定保留 `unassessed`。
正确拒绝或必要问询可以匹配测试预期，但应将“业务交付完成”记为否。
状态和原因码必须使用被测版本的实际契约；本模板的中文描述不是新 API 枚举。

| --- | --- | --- | --- | --- |
| S1 | 创建目标与约束 | `<...>` | `<执行或必要问询>` | `<目标、预算初值>` |
| S2 | 回答 / 断线 / 暂停后恢复 | `<...>` | `<只处理有效问题；继续剩余工作>` | `<约束保留、累计消费、幂等、不串用户>` |
| S3 | 修改目标或取消 | `<...>` | `<按合法状态处理；旧问题失效>` | `<新 revision；旧证据不能无条件继承验收>` |

不要以最后一轮成功代替场景成功。当前 Task 跨 Run continuation 与同一 Run 局部恢复不同；
未交付的恢复或并行问询能力应标为范围外/待实现，不写成现有成功路径。

## 4. 示例：同一业务改善与压力并存

**仅使用合成资料，以下不是实际公司业绩。**

- 输入：“甲公司有哪些亮点？哪些业务表现较好？哪些方面承压？”
- E1：“2026 年第一季度，甲公司寿险营运利润 100 亿元，同比增长 6%。”
- E2：“同期，甲公司寿险新业务价值率 23%，同比下降 4 个百分点。”
- 范围：只覆盖寿险、该期间和这两个指标，不假设已覆盖公司所有业务。

| 要求 | 应有交付 | 判定依据 |
| --- | --- | --- |
| R1 亮点 | 寿险利润增长及准确数值 | E1，主体、期间、单位一致 |
| R2 较好方面 | 利润指标改善；明确评价范围 | 不将单指标增长推导为跨业务排名 |
| R3 承压方面 | 价值率下降及准确幅度 | E2；下降百分点与百分比不混淆 |
| R4 归纳与范围 | 同一业务改善与压力并存，未覆盖业务不评价 | 同时保留 E1/E2；R4 是标注的输出完整性要求，不冒充用户原话 |

| 输出变体 | 事实正确 | 任务完整 | 案例预期 |
| --- | --- | --- | --- |
| 按上述依据归纳并引用，披露范围 | 是 | 是 | 正向通过 |
| 只罗列 E1、E2 原句 | 可正确 | 否 | 应检出缺少分析 |
| 只加“亮点/承压”标题，没有分析 | 可正确 | 否 | 应检出伪完整 |
| 只回答利润增长 | 可正确 | 否 | 应检出遗漏反面证据 |
| 将 100 改为 999 或改错期间 | 否 | 不可通过 | 应检出事实错误 |
| 宣称“全集团最差业务” | 无支持 | 不可通过 | 应检出越出证据的判断 |

这一样例验证的是有界业务归纳。一般原因分析、未来预测和跨业务排名需要另行定义资料、口径与评判标准。

## 5. 用例选题清单

| 任务涉及的能力 | 至少考虑的对照 |
| --- | --- |
| 意图/改写 | 原始对象与期间保留；不擅自添加年份；所有必需子问题到达查询 |
| 复合检索/表格 | 必需查询齐全；表格负面指标保留；重复来源不充数；主体不跨片段错配 |
| 分析回答 | 事实与完整性分别判断；保留条件和反证；不支持的结论保持未知 |
| 问询 | 可检索事实先查；可选偏好可默认；必需输入不能猜；无回答不算同意 |
| 证据要求 | 时效使用来源日期；来源去重；适用性与冲突；确认不能替代证据 |
| 流程简化 | lite 保留必需校验；上限阻止升级时不删要求；预览与实际路径一致 |
| 修复/续跑 | 格式修复与证据补检分开；有限预算；旧问题失效；约束及消费不丢失 |
| 只读工具/交付物 | 每个必需步骤绑定已验证结果；工具成功不替代答案或交付物验收 |
| Dashboard/Operator Chat | 配置可发现、保存重载、冻结版本绑定、状态与恢复回路的实际渲染 |
| 未来业务写入 | 单独评审范围与权限后验证幂等、结果核对和未知结果恢复；当前生产禁用 |

## 7. 套件质量统计与维护

开发回归集与独立验收集分开管理；独立验收集在冻结候选后执行，避免按结果反复调参再报告为未见样本。
真实模型预先声明重复次数并保留全部运行，不能仅选最好的一次。基准、模型或数据版本变化须标为基准迁移。

以下为业务质量记录口径，不修改现有 Analyzer 指标或发布阈值。先记录业务预期为
“可完成 / 应澄清 / 应拒绝 / 预期未知”，再分组统计；缺失与未评估不从分母消失，空组记 null。

| 指标 | 分子 / 分母与补充要求 |
| --- | --- |
| 质量评估覆盖 | 已有独立通过或失败判定的必需案例 / 该组全部必需案例 |
| 完整正确率 | 独立判定完整正确且治理通过的可完成案例 / 全部必需可完成案例 |
| 错误完成率 | 独立判错但系统判完成的案例 / 全部系统判完成案例；同时报告其中未评估数量 |
| 不必要澄清率 | 无需澄清却触发问询的案例 / 全部已标注无需澄清案例 |
| 正确拒绝率 / 过度拒绝率 | 正确拒绝 / 应拒绝案例；错误拒绝 / 可完成案例；分别报告 |
| 缺口恢复成功率 | 补检后完整正确且治理通过 / 预先标注可恢复的缺口案例 |
| 成功任务成本 | 独立验证成功任务的耗时、调用和已知成本分布；另列失败成本和未知 usage |

具体业务阈值由对应需求与 suite/profile 预先约定；不要把固定合成样例的通过率作为总体质量概率。
已发现回归加入开发集并关联缺陷；改 rubric、修参考事实或调整预期都记录原因与版本，不能静默迁就当前输出。

## 9. 总结分析与引用原文用例补充（ADR-0260）

每个分析性业务案例补充以下记录；参考答案可有多种表述，不逐字匹配生成正文。

| 检查项 | 案例必须说明的内容 |
| --- | --- |
| 用户要求 | 原问题及全部子问题；哪些可查、哪些需要用户信息 |
| 关键结论 | 可接受的总结、比较或推导；禁止的过度推断 |
| 引用绑定 | 结论片段 → 原文片段 → Accepted Evidence citation |
| 条件 | 适用对象、事件时点、期间、单位、公式、例外和前提 |
| 完整性 | 每项 answered / needs_evidence / needs_user_input 的业务依据 |
| 可见输出 | 结论旁的原文编号与完整原文块；表格可解释，但引文不得伪造 |
| 复核 | support / conditions / coverage 的预设判定与修复次数 |
| 状态与成本 | 回答状态、Task 验收状态、额外复核调用及累计预算 |

至少按受影响行为选择对照：正确改写合并；表格转述；真原文但错误推论；
遗漏免责或条件；个人信息不足；假引文/错来源；单边回答伪称完整；
复核拒绝、异常、超预算；修复后再次复核；证据变更导致旧复核失效。
例如“30 岁是否适合买”必须区分当前年龄与身故时到达年龄，不能从条款比例直接推出
购买适合性，且应明确仍需哪些个人信息。用合成条款测试机制，不冒充具体产品正式结论。

合成 fake-provider 回归只证明契约与流程；真实模型质量另用独立业务标注验证。
同模型的第二次复核可能重复第一次错误，不作为独立真值。

### 部分回答与主动问询对照（ADR-0261）

- 产品事实与个人适合性混合问题：自主模式也必须先检索、部分作答、明确限制并主动提问。
- 身份/权限/对象/工具输入不足：不得借部分回答绕过硬前提。
- Planner 重提已延后的同一字段：不应重新阻断独立检索。
- Task 部分交付后为 waiting_for_input；轮次耗尽为 paused，不能 complete。
- 用户补充后不重复询问已绑定的字段，继续处理剩余子问题。
- 无独立必需检索的请求不得仅凭 answer_context 分类自动扩大执行范围。
